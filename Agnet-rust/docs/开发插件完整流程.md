# 开发一个插件必须做的几件事（按顺序）

本文档告诉你：写一个新插件，从零到跑通，每一步做什么、在哪里做。

---

## 第一步：确定插件类型

只有两种插件，选一个：

| 类型 | 对应 Trait | 干什么用 | 例子 |
|------|-----------|---------|------|
| **SlotPlugin (槽口插件)** | `impl SlotPlugin` | 在 Pipeline 管道里按阶段顺序执行，同步处理 | LLM 调用、工具执行、记忆读写 |
| **ServicePlugin (服务插件)** | `impl ServicePlugin` | 后台独立运行，异步提供服务，注册 Provider | 日志服务、存储服务、HTTP 服务 |

---

## 第二步（关键）：定义共享类型契约

> **这条是架构红线**：如果你的插件引入了**被其他插件引用**的数据类型或 Provider trait，
> **必须先放在 `shared_types` 中**，再被双方引用。禁止一个插件直接引用另一个插件的内部类型。
>
> 详细规则见 [`protocol-shared_types契约协议.md`](protocol-shared_types契约协议.md)。

**什么时候需要这步？**

| 场景 | 举例 | 必须做 |
|------|------|--------|
| 你的 Service 提供能力，其他 Slot/Service 要通过 Provider 调用 | `ToolProvider` trait、`MemoryProvider` trait | ✅ 定义在 `shared_types` |
| 你的 Slot 写入 StepContext，其他 Slot 要读取 | `Thought`、`Observation`、`IdentitySection` | ✅ 定义在 `shared_types` |
| Slot 和 Service 之间传递复杂数据结构 | `ToolDefinition`、`MemoryFileEntry` | ✅ 定义在 `shared_types` |
| 类型只在本模块内部使用，不跨插件 | 组件内部中间状态、私有配置 | ❌ 不需要，留在模块内 |

**操作**：

```rust
// src/shared_types/mod.rs — 添加你的共享类型

// ── 1. Provider key 常量（注册名，双方引用，防止拼写不一致） ──
/// Slot 通过此 key 在 `provider_raw()` 中查找对应的 Provider
pub const PROVIDER_TOOL: &str = "tool";

// ── 2. Provider trait（契约层，不归属于任何一方） ──
// 
// Provider trait 的定义位置规则（重要）：
//   ✅ 定义在 shared_types 中，不在任何一方的模块内部
//   ✅ 谁先写代码，谁负责先把 trait 放进 shared_types
//      → 先开发 Service，Service 开发者放 trait 进去并 impl
//      → 先开发 Slot，Slot 开发者放 trait 进去，Service 后来 impl
//   ✅ 消费方（Slot）通过 `use crate::shared_types::XXX` 引用
//   ✅ 提供方（Service）通过 `impl XXX for YYY` 实现
//   ❌ 禁止 trait 定义在 Service 或 Slot 的内部模块中
//
#[async_trait]
pub trait ToolProvider: Send + Sync {
    fn list(&self) -> Vec<ToolDefinition>;
    async fn execute(
        &self,
        tool_name: &str,
        arguments: serde_json::Value,
        timeout: std::time::Duration,
    ) -> Result<String, ToolError>;
}

// ── 3. 跨插件数据结构 ──
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ToolDefinition {
    pub name: String,
    pub description: String,
    pub parameters: serde_json::Value,
}
```

**使用方式**：

```rust
// 服务端注册时用常量（在 ServicePlugin::start() 中）：
use crate::shared_types::{PROVIDER_TOOL, ToolProvider};
ap.register_provider(PROVIDER_TOOL, Arc::new(my_tool_provider_impl));

// 消费端查找时也用常量（在 SlotPlugin::run() 中）：
use crate::shared_types::PROVIDER_TOOL;
let raw = ap.provider_raw(PROVIDER_TOOL)?;
```

**核心规则**：`register_provider` 和 `provider_raw` 使用**同一个常量**，禁止写裸字符串（否则两边各写各的，运行时才发现找不到）。

**依赖方向规则**（违反此规则 = 架构违规）：

```
✅ 正确：                ❌ 错误：
                         
shared_types ← 实现方    ServiceA::内部类型 ← 消费方直接 use
    ↑    ↓               
    │    └── 消费方引用    (ServiceA 的内部变更会炸掉消费方)
    │                     
    └── 实现方引用         
```

## 第三步：写插件代码

在 `src/plugins/` 下创建你的插件文件（SlotPlugin 放 `slots/`、ServicePlugin 放 `services/`）。创建完成后，必须在其父 `mod.rs` 中添加模块声明：

```rust
// SlotPlugin → src/plugins/slots/mod.rs
pub mod my_slot;      // ← 添加这一行

// ServicePlugin → src/plugins/services/mod.rs
pub mod my_service;   // ← 添加这一行
```

模块声明链为：`src/lib.rs` → `src/plugins/mod.rs` → `src/plugins/slots/mod.rs`（或 `services/mod.rs`）→ 你的插件。

> **模块内集成红线**：插件代码写完后，必须验证对外接口（`run()`/`start()`/`chat()` 等）**实际调用了**内部组件。仅把组件定义在 struct 字段中或注册到 Orchestrator 但不在主执行路径中触发，视为未完成。见 [`protocol-模块内部组件协议.md §12`](protocol-模块内部组件协议.md) 集成检查清单。

### SlotPlugin 模板

```rust
use async_trait::async_trait;
use aagnet::core::slot::{SlotPlugin, SlotDirective};
use aagnet::core::access::SlotAccessPoint;
use aagnet::core::types::error::PluginError;
use aagnet::core::types::plugin::PluginInitContext;
use aagnet::shared_types::Message;

pub struct MySlot;

#[async_trait]
impl SlotPlugin for MySlot {
    fn name(&self) -> &str { "my_slot" }

    async fn init(&mut self, ctx: &PluginInitContext) -> Result<(), PluginError> {
        // ctx.plugin_config  ← 你的配置
        // ctx.agent_config   ← 全局配置（由 CoreConfig::to_agent_config() 注入）
        // ctx.data_dir       ← 你的私有数据目录
        Ok(())
    }

    async fn run(&mut self, ap: &mut dyn SlotAccessPoint) -> Result<SlotDirective, PluginError> {
        // ap.messages()       ← 当前对话历史（返回 &[Message]）
        // ap.session_id()     ← 当前会话 ID
        // ap.provider_raw()   ← 找其他 Service 注册的能力
        // ap.write_observation()  ← 写工具结果（类型擦除 Box<dyn Any>）
        // ap.request_jump()   ← 跳转到指定阶段
        Ok(SlotDirective::Continue)
    }

    async fn shutdown(&mut self) -> Result<(), PluginError> {
        Ok(())
    }
}
```

### ServicePlugin 模板

```rust
use async_trait::async_trait;
use aagnet::core::service::{ServicePlugin, ServiceSignal};
use aagnet::core::access::ServiceAccessPoint;
use aagnet::core::types::error::PluginError;
use aagnet::core::types::plugin::PluginInitContext;
use std::sync::Arc;

pub struct MyService;

#[async_trait]
impl ServicePlugin for MyService {
    fn name(&self) -> &str { "my_service" }

    async fn init(&mut self, ctx: &PluginInitContext) -> Result<(), PluginError> {
        Ok(())
    }

    async fn start(&mut self, ap: ServiceAccessPoint) -> Result<(), PluginError> {
        // 注册 Provider：
        // ap.register_provider("my_capability", Arc::new(MyProvider));
        Ok(())
    }

    async fn handle_signal(&mut self, signal: ServiceSignal) -> Result<(), PluginError> {
        match signal {
            ServiceSignal::GracefulShutdown => { /* 优雅关闭 */ }
            ServiceSignal::ConfigReload => { /* 配置重载 */ }
            _ => {}
        }
        Ok(())
    }

    async fn stop(&mut self) -> Result<(), PluginError> { Ok(()) }
    async fn shutdown(&mut self) -> Result<(), PluginError> {
        // ap.unregister_provider("my_capability");  // 反注册
        Ok(())
    }
}
```

## 第四步：注册到运行时

打开 `main.rs`（或者项目入口文件），把你的插件加进去。

### 注册 SlotPlugin

> **关键**：Slot 在加入 Pipeline 之前**必须调用 `init()`**。`init()` 由注册方（通常是 `main.rs`）负责调用，Pipeline 不自动调用。

```rust
use aagnet::core::pipeline::Pipeline;
use aagnet::core::phase::Phase;
use aagnet::core::runtime::AgentRuntime;
use aagnet::core::types::plugin::{PluginInitContext, AgentConfig};
use std::path::PathBuf;

#[tokio::main]
async fn main() {
    // 1. 创建 Slot
    let mut my_slot = MySlot;

    // 2. 调用 init()——这步不能省略
    let ctx = PluginInitContext::new(
        "my_slot",
        serde_json::json!({}),          // 插件配置
        AgentConfig::default(),          // 全局配置
        PathBuf::from("./data/my_slot"), // 数据目录
    );
    my_slot.init(&ctx).await.expect("MySlot.init() 失败");

    // 3. 注册到 Pipeline
    let pipeline = Pipeline::with_recommended_phases()
        .add_slot(Phase::think(), Box::new(my_slot));

    let runtime = AgentRuntime::new_with_config(pipeline, agent_config);
    runtime.run().await;
}
```

**为什么必须手动调用 init()？**
- `Pipeline::add_slot()` 是同步 builder 方法，无法执行 `async fn init()`
- `init()` 的失败必须被妥善处理（`expect` 或 `map_err`），不能让 Slot 以未初始化状态进入 Pipeline
- 如果忘记调用 `init()`，Slot 的 `run()` 必须返回 `PluginError::Runtime`（不允许退化运行）

### 注册 ServicePlugin

```rust
use aagnet::core::runtime::AgentRuntime;
use aagnet::core::pipeline::Pipeline;

#[tokio::main]
async fn main() {
    let pipeline = Pipeline::with_recommended_phases();
    let runtime = AgentRuntime::new_with_config(pipeline, config);

    // 启动 Service
    let ap = runtime.create_service_access_point();  // ← 使用注入的配置
    let mut service = MyService;
    service.init(&ctx).await.unwrap();
    service.start(ap).await.unwrap();

    runtime.run().await;
}
```

## 第五步（可选）：如果插件需要新的外部依赖

如果插件需要使用当前 `Cargo.toml` 中不存在的 crate（例如发邮件需 `lettre`、操作数据库需 `rusqlite`），在 `Cargo.toml` 的 `[dependencies]` 中添加：

```toml
lettre = "0.11"
```

添加后运行 `cargo build` 确认编译通过。如果完全复用已有依赖，可以跳过此步。

---

## 第六步（可选）：如果插件需要用户配置

如果用户需要自定义参数（比如 API key），在 `config/config.toml` 里加一段：

```toml
[plugins.my_slot]
my_param = "my_value"
another_param = 42
```

你的插件在 `init()` 时自动收到：

```rust
async fn init(&mut self, ctx: &PluginInitContext) -> Result<(), PluginError> {
    if let Some(cfg) = &ctx.plugin_config {
        // cfg["my_param"] → "my_value"
        // cfg["another_param"] → 42
    }
    Ok(())
}
```

**不需要配置的插件可以不在 config.toml 里出现。** 程序会用默认值运行。

---

## 第七步：如果插件需要暴露能力给其他插件

> **红线**：Provider key 必须使用 `shared_types` 中定义的常量，**禁止裸字符串**。
> 如果 key 尚未在 shared_types 中定义，请先回到第二步添加。

你的 ServicePlugin 在 `start()` 里注册 Provider：

```rust
use crate::shared_types::PROVIDER_MY_CAPABILITY;

pub struct MyProvider;

async fn start(&mut self, ap: ServiceAccessPoint) -> Result<(), PluginError> {
    ap.register_provider(PROVIDER_MY_CAPABILITY, Arc::new(MyProvider));
    Ok(())
}
```

其他插件通过 `provider_raw()` 找到你：

```rust
// 在其他 SlotPlugin 或 ServicePlugin 中
use crate::shared_types::PROVIDER_MY_CAPABILITY;

async fn run(&mut self, ap: &mut dyn SlotAccessPoint) -> ... {
    let provider = ap.provider_raw(PROVIDER_MY_CAPABILITY)
        .and_then(|p| p.downcast::<MyProvider>().ok());
    // 使用 provider
}
```

## 第八步（强制）：Provider 对接检查清单

Provider 注册方和消费方由不同的 AI 独立开发时，**必须在 cargo check 通过之后额外执行以下检查**，否则对接断裂不会被任何编译器捕获。

### 检查清单

```
□ 1. Provider key 是否在 shared_types 中定义为常量？
   → grep 'pub const PROVIDER_' src/shared_types/
   检查：注册方用 `register_provider(PROVIDER_XXX, ...)`
        消费方用 `provider_raw(PROVIDER_XXX)`
   如果 key 不匹配，运行时会返回 None，编译不报错。

□ 2. Provider trait 是否在 shared_types 中定义？
   → grep 'pub trait' src/shared_types/
   检查：定义在 shared_types 中，不在任何插件的内部模块中。
   如果 trait 定义在 services/some_module/ 内部，
   另一个 slots/ 无法引用它（违反协议红线）。

□ 3. 消费方 downcast 的类型是否与注册方的类型一致？
   注册方：register_provider("xxx", Arc::new(SomeConcreteType))
   消费方：provider_raw("xxx")?.downcast::<Arc<SomeConcreteType>>()
   检查：SomeConcreteType 在两边是同一个类型。
   如果类型不匹配，downcast 返回 Err，运行时静默降级。

□ 4. 如果消费方 downcast 到 Arc<dyn TraitName>，
    注册方是否确保具体类型实现了该 trait？
    注册方：Arc::new(MyProvider)   // 需要 impl TraitName for MyProvider
    消费方：downcast::<Arc<dyn TraitName>>()
    检查：grep 'impl TraitName for' src/plugins/services/
    如果缺少 impl，编译可能通过但运行时 downcast 失败。

□ 5. 模块内部组件是否已集成到主执行路径？
    → 见 `protocol-模块内部组件协议.md §12` 集成检查清单
    检查：对外接口（run_loop/execute/chat）实际调用了已注册组件的业务方法。
    如果 struct 字段存在但 clippy 报 "field is never read"，判定未完成。
```

### 验证方法

```bash
# 1. 列出所有 Provider 常量，确认注册方和消费方引用了同一个
grep -rn "PROVIDER_" src/ | grep -E "register_provider|provider_raw"

# 2. 列出所有 `impl <ProviderTrait> for` 确认实现存在
grep -rn "impl .*Provider for" src/plugins/services/

# 3. 检查 shared_types 中是否包含了所有跨插件 trait
grep "pub trait" src/shared_types/*.rs
```

## 完整流程

```
你写代码                             框架自动做
─────────                           ──────────
1. 确定类型 (Slot / Service)
2. 定义 shared_types 契约（如需要）   → 跨插件类型统一定义，避免循环依赖
   ├── Provider trait                → 不归属于任何一方，谁先开发谁放
   ├── Provider key 常量             → register / provider_raw 双方引用
   └── 跨插件数据结构
3. 写 impl SlotPlugin / ServicePlugin        crate 根 → plugins/mod.rs
   并在 slots/mod.rs 或 services/mod.rs       → 父 mod.rs → 你的文件
   加模块声明                               → Rust 编译器能编译
4. 注册到 main.rs                    → Pipeline 知道什么时候执行它
                                     → AgentRuntime 管理它的生命周期
5. (可选) 加新依赖到 Cargo.toml     → cargo build 编译通过
6. (可选) 在 config.toml 加配置      → ConfigLoader 读取，init() 时收到
7. (可选) register_provider()        → 其他插件可以通过 provider_raw() 找到你
8. 🔴 Provider 对接检查清单          → 编译器不检查这个，必须人工/脚本执行
```

## 红线

| 编号 | 红线 |
|------|------|
| 1 | 插件不要直接访问 AgentRuntime、StepContext 的内部字段——只能通过 `SlotAccessPoint` / `ServiceAccessPoint` 通信 |
| 2 | 不要越过协议直接引用其他插件的具体类型——通过 `provider_raw()` + `downcast` 调用 |
| 3 | 跨插件共享的数据类型和 Provider trait **必须**定义在 `shared_types` 中，禁止在插件间 `use` 内部路径 |
| 4 | `config.toml` 只写用户需要自定义的参数——不要写死敏感信息在代码里 |
| 5 | 每个插件必须实现完整生命周期——`init` / `run`(或`start`) / `shutdown` 都要能正常执行 |
| **6** | **Provider 对接必须通过第八步检查清单验证——编译器不检查 key 和类型是否匹配** |
| **7** | **模块内部组件必须集成到主入口**——仅注册 Component 到 Orchestrator 但不在 `run_loop`/`execute` 中调用 `process()`，或 struct 字段存了子服务但不在方法中读取，都视为未完成集成。见 [`protocol-模块内部组件协议.md §12`](protocol-模块内部组件协议.md)。 |
